# Экспериментальная тема «Планер»

## Включение

Отправить `/new`, затем в «Темах» выбрать «Планер». Команда только разблокирует тему:
она не включает её автоматически. Раздел доступен также через `/themes` и кнопку
«Темы» в профиле. Классическая тема остаётся по умолчанию для существующих и новых
пользователей; выбор индивидуален, сохраняется в БД и обратим.

## Интерфейс

- Меню: задания, неделя, расписание, баллы, проверка и настройки.
- «Моя неделя»: пары и несданные работы за выбранную календарную неделю, переходы
  между неделями, список заданий недели. Отсутствие данных расписания не выдаётся
  за подтверждение отсутствия занятий.
- Задания: фильтры «Несданные», «Делаю», «Все», страницы по четыре работы.
- Карточка: официальный статус, срок, текст задания, баллы, рецензия, личный
  прогресс, заметка, история последних трёх изменений и ссылка в Timeline.
- Прогресс: «Не начато», «Делаю», «Готово к сдаче». Это личные пометки, которые
  не отправляются в вуз и не отключают напоминания.
- Напомнить позже: 30 минут, час, вечером в 19:00, завтра в 09:00; отмена.
  Повторная установка заменяет предыдущую. При официальной сдаче напоминание снимается.
- Настройки: уведомления, набор порогов 24/12/1 или 48/24/1 либо только час,
  тихие часы, срочные часовые уведомления ночью, время дайджеста и расписания,
  отключение отдельных предметов. Время — **МСК**, как в существующем проекте.
- Изменения расписания показывают добавленные/убранные пары и изменения времени,
  аудитории, преподавателя; снимок хранится в БД. Первый снимок не вызывает рассылку.

## Фоновая работа

Для всех тем синхронизация с Timeline проходит в **00:00, 06:00, 12:00, 18:00 МСК**.
Ручная проверка остаётся доступной с существующим ограничением MIN_CHECK_GAP.
Персональный `/interval` больше не задаёт частоту фоновой синхронизации.
LOW_POWER_MODE влияет на частоту дайджеста и контроля расписания; CHECK_HOURS
и SCHEDULER_TICK больше не управляют синхронизацией статусов.

Сохранённые дедлайны проверяются каждую минуту без входа на сайт вуза. Для классической
темы сохраняется прежний формат уведомлений. Планер имеет отдельную дедупликацию,
тихие часы и отложенные напоминания. Флаги его доставки меняются после успешного ответа
Telegram; сбой оставляет напоминание для повторной попытки. Изменения и новые задания
попадают в постоянную очередь в той же транзакции, что и обновление работы. Очередь
переживает перезапуски, повторяет доставку с увеличением интервала и ждёт окончания
тихих часов. При смене темы на классическую очередь Планера приостанавливается.
История доставленных событий хранится 90 дней; ожидающие доставки события не удаляются.
После фактической отправки и до фиксации БД аварийное завершение процесса может дать
повторное сообщение: внешняя доставка Telegram и SQLite не образуют общую транзакцию.

Неполная/некорректная ведомость Timeline теперь отменяет синхронизацию, чтобы не удалить
работы из-за сбоя при загрузке следующей страницы. Данные карточек могут отставать от
вуза на время до следующей шестичасовой синхронизации; локальная проверка сроков этого
не устраняет. Для актуализации используется «Проверить».

## Миграция и применение

Добавляются колонки настроек/прогресса и таблица planner_event. Существующие записи
остаются в классической теме; пароли и токены не меняются. Перед обновлением следует
иметь резервную копию существующей SQLite базы и ключа CRED_KEY.

В Docker код запечён в образ. Для применения:

```sh
git pull
docker compose up -d --build bot
```

## Проверки

```sh
python -m compileall -q app tests
python tests/smoke_test.py
python tests/planner_test.py
```

Проверки изолированы от реальных Timeline и Telegram. CI запускает их на Python 3.12.
Тесты Планера проверяют разблокировку и откат темы, изоляцию данных, заметки, тихие
часы, отложенные напоминания, повторную доставку, миграцию и конкретный diff расписания.
